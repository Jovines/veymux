# 中转连接的一并更新

PWA 的界面资源由打开页面的入口提供，目标服务更新不会自动更新入口的资源。更新提示和设置中的“一并更新并重启”会说明实际中转的名称、界面来源，以及仅更新目标不能更新全部界面功能的原因。确认框列出参与更新的服务，说明重启会短暂中断其他经中转连接的设备。

参与者由当前已认证连接、保存的服务身份和路线确定：当前目标、实际使用的中转、提供当前界面的入口。去重后按目标、中转、界面入口排序；不能把远端目标保存的中转 URL 当成目标的直连地址。直连远端但仍使用其他入口界面时，也包括界面入口；未使用的备用中转不参与。入口身份记录冲突或无法确认时，停止操作并提示重新连接。

## 执行流程

1. 每台服务分别使用此设备的加密身份检查完整服务授权。只有中转通行权限不足以更新中转，任何一端无管理权限时不执行安装或重启。
2. 获取各自更新状态，安装尚未准备好的组件，并等待安装结果。所有参与者至少达到目标已确认的版本，目标待更新版本变化须重新确认。
3. 调用各端 `/api/terminal/update/prepare-restart`，检查安装文件、待更新版本和受管重启入口。预检不会触发重启，正式重启前会再次检查。旧版服务缺少此接口时仅对 404 兼容，仍保留旧 `/restart` 的版本、安装与 supervisor 校验；因此旧版服务的重启条件失败可能发生在目标已经更新之后。
4. 依次重启并通过新的加密连接读取运行版本。每次安装和重启的 POST 仅发送一次；响应因断线丢失时只重新读取版本，不自动重发写请求。未确认目标恢复前不会重启中转。
5. 所有服务恢复后，刷新入口的 Service Worker，等待新资源安装和激活，保存所有保留工作区的草稿，重新加载顶层页面。无 Service Worker 的首次加载直接重新加载顶层页面。资源更新失败不显示界面已更新成功。

进度和失败原因保留在设置及侧栏。部分更新后，即使目标已是新版本，一并更新按钮仍可用；重试跳过已更新的服务。操作期间允许正常重连，页面离开、服务切换或授权失效会停止后续操作。此流程由当前页面执行，关闭 PWA 会停止后续步骤；重新打开后可通过同一按钮继续完成尚未更新的服务。

## 验证范围

- 状态回归覆盖更新顺序、旧版预检兼容、安装与重启失败、确认版本变化、权限不足、断线响应核对、部分完成重试和更新后的界面加载。
- 独立测试服务运行真实 WSS、Noise、入口中转和设备鉴权；安装过程使用隔离的更新 runner，不执行真实 npm 安装或重启生产服务。验证首次无 Service Worker 控制、旧 preload 上传方法未被调用，以及业务请求仅经加密通道进入服务端内部 HTTP。
- Chrome 隔离组件验证覆盖 320、390 和 1440 像素宽度的确认、取消、成功、权限失败、安装失败、部分完成和重试，检查操作按钮可达和横向溢出。
- Chrome 真实 Service Worker 验证覆盖首次无控制器、保留工作区触发顶层重载、旧缓存切换新版缓存、草稿保存，以及资源更新失败后不错误重载。没有使用浏览器模拟代替真实 macOS/iOS PWA 验收；这两类实机路径仍待验证。

现有旧版界面无法凭目标服务更新获得此流程，需要先更新一次提供界面的入口并重新加载 PWA。后续更新即可使用一并更新入口。

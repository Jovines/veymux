# 共享会话功能白名单

共享会话使用独立界面，只开放明确授予的能力，不从完整服务菜单中逐项排除功能。

| 授权来源 | 开放能力 |
| --- | --- |
| 已认证 session-list 中的会话 | 查看终端和对话 |
| 该会话 `canWrite === true` | 输入、发送消息及会话附件 |
| 该会话 `canResize === true` | 调整远端终端网格 |
| 明确授予的 android / computers / directories | 对应手机、电脑、文件入口，各资源继续执行自己的查看/控制或读/写权限 |

`sessionCapabilities.ts` 统一投影上述白名单。共享能力不含通配符；写入权限不会附带待办提示、再次分享、重命名、销毁等所有者操作，新增能力也不会自动获得。共享资源栏只枚举已登记并已授权的资源种类。

`SessionAccessView` 用同一投影控制终端、对话及资源入口，并通过 `SessionCapabilitiesContext` 提供给公共组件。公共组件使用 `useSessionCapabilities().has(...)` 正向判断功能。共享上下文存在但未提供会话能力时，默认没有任何会话操作权限；`SessionChatView` 的 `canWrite` 参数只能进一步收紧权限，不能越过白名单。

完整服务仍由 `SecureAccessGate` 的已认证 `fullService` 分支进入，沿用完整服务功能。共享内容在捕获阶段隔离应用右键菜单，不影响选中文字后的原生复制，也不拦截资源侧栏里远程电脑自身的鼠标操作。

前端白名单用于控制界面和交互，服务端现有 action、session scope 与 resource grant 校验仍是实际授权边界。不得绕过页面加密 fetch / secureSocket 或在失败后降级到业务 HTTP。

## 免证书分享入口与本机显示清理（2026-10-26）

局域网分享链接的 HTTP `/connect` 直接加载邀请界面，接受后以邀请中固定的服务身份建立 Noise 加密通道。该端口只提供页面、静态资源和加密 WebSocket，普通 `/api` 请求拒绝；终端、对话和文件继续使用页面的加密 fetch / secureSocket。HTTP WebSocket 限制同源，使用中转还必须提交原有的一次性目标路由票据。`/certificates` 保留可选的 CA 安装与 HTTPS 入口。HTTP 不认证页面代码来源，应用加密并不使其具备 HTTPS 的来源保证。

macOS 客户端粘贴同一个邀请时，仍解析原始 HTTPS 目标，走客户端证书审核与信任；浏览器选择 HTTP 传输的参数不会改变原始邀请描述。HTTP 页面没有 Service Worker，UUID 使用浏览器可用的 getRandomValues 生成，不伪造安全上下文或 WebCrypto 能力。

对话中的「清空显示」只保存当前设备、服务和会话的显示分界，既不删除服务端消息，也不修改 Agent 上下文。刷新后仍隐藏旧记录，新消息继续显示，「恢复旧记录」可撤销显示分界。分页加载的旧消息同样受分界过滤。

真实 Chromium 已验证远程 HTTP 地址直接接受邀请及「添加服务」粘贴邀请，无 CA 安装或 TLS 校验豁免，且首次加载没有 Service Worker。只读越权输入被拒绝，未发现明文业务请求。当前任务会话实际清空显示、刷新保持隐藏、恢复显示通过，服务端记录保留。客户端 HTTPS 证书审核有自动化覆盖；锁屏 Mac 的真实原生点击尚未验收。

## 权限复查（2026-10-25）

本轮发现并修复两个缺口：会话附件上传成功后，预览仍被文件目录授权拦截；只读会话的文件树仍显示不能执行的「插入到终端」动作。后者由输入白名单拦截，没有取得写入能力，但入口应隐藏。

`sessionAttachmentAccess.ts` 统一上传与读取的 Session 附件根路径。已认证目录仅向可查看的 Session 投影 `attachmentRoot`；共享页用它开放该会话附件的预览，不因此增加文件侧栏。服务端只允许查看权限读取对应根路径内已有附件的 read / blob / video / download / HTML preview，不允许列举、搜索、写入或删除。精确 URL、重复参数、真实路径、跨 Session hash 和目录外符号链接继续校验，每个请求及流式响应继续检查撤销与到期。通过原加密 fetch / secureSocket，失败不降级。

隔离服务的真实 Chromium 验证覆盖只读 / 可操作 / 独立目录读写授权：会话历史、终端流、命令输入、附件上传与读取、共享文件预览、编辑保存与目录上传；手工构造其他会话、设置、原始库存、组/任务、Git、目录外文件及未授权手机/电脑请求被拒绝。证书测试使用自动化浏览器的临时证书校验豁免，不代表设备已实际安装 CA。根授权、tmux socket、会话和文件均在独立临时目录，未对用户会话输入测试命令。

权限专项、附件直连/中转回归和两组终端尺寸回归通过。扩展的 ChatFileNavigation 测试因现有测试环境缺少 matchMedia 失败；仓库外补齐浏览器 API 后 4/5 通过，剩余标题数量断言期望 2、实际 1，不在本轮改动范围。完整类型检查仍有 chatComposer.browser.tsx 的既有上传返回值类型错误，不改写他人 WIP。手机投屏与 VNC/RDP 控制的权限和协议过滤有自动化覆盖，本轮未用真实 Android、macOS/iOS 或远端桌面实机验收。

重启复查还发现：tmux 会话仍存活时，服务重启后的共享目录只有库存记录、尚无 backend 连接，窄授权页面因此显示空会话。现由已认证 session-list 在逐个检查 session.view 后调用 `restoreSharedFederationSession`，只对现有库存中的 tmux 记录使用精确目标 `=name` 检查，再经原库存打开锁重新挂载；不创建 Shell，不恢复已删除的 tmux，不挂载未授权记录，也不提供估算网格。授权撤销/到期后不会触发恢复。

最终权限专项 19 个文件 127 项通过；设备/协议相关 4 个文件 50 项通过（含部分重叠用例）；真实 WSS + Noise 直连/中转传输 2 项通过；终端尺寸单元回归 192 项及两组浏览器/tmux 回归通过。生产客户端构建、服务端编译通过，部署至 9834，health、受管进程和实际前端入口核对通过。隔离浏览器确认修复后的只读侧栏不再显示插入动作，重启后无需所有者开终端即可恢复已授权 tmux。
